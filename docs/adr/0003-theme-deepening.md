# ADR 0003: テーマの深掘り（原作の設定をゲームの仕組みにする）

状態: 提案（2026-09-30。オーナー指示「テーマを深掘りしてゲームに浸透させたい」への回答。実装は段階的）

## 目的と方針
- 飾りではなく、**「弱点を見つけて克服する」というアプリの目的を、原作の設定で語り直す**。演出は仕組みの後ろに付く。
- 制約（これまでの決定を覆さない）: 打鍵の判定・計測は変えない／指標は打鍵ログから再計算する（保存しない）／コアに固有名詞を置かない（テーマのデータに置く）／色だけで伝えない／演出の強さ（標準・控えめ・オフ）に従う。
- 原作の内容に基づく対応づけは、**遊びの意匠**であって、打鍵学習の効果の根拠ではない。画面にもそう書く。

## 研究 1: 原作の設定（資料で確認できたもの）
出典は末尾。ネットワーク制限で本文は取得できず、検索結果の要約で確認した。要約にない項目は「記憶」と明記する。

- **四大行**: 纏（オーラを身にまとう）／絶（オーラを断つ。気配を消す・疲労回復）／練（オーラを高める）／発（練で高めたオーラを解き放つ＝自分の能力）。応用技に周・隠・凝（オーラを目に集める）・円（範囲を探る）・堅・硬・流（記憶）。
- **六系統と六性図**: 強化・変化・放出・操作・具現化・特質。六角形の並びは **強化―変化―具現化―特質―操作―放出―（強化）**。隣り合う系統は相性が良く、向かい合う系統（強化―特質、変化―操作、具現化―放出）は最も遠い。習得の効率は、自分の系統 100%、隣 80%、その次 60%、向かい 40%（資料によって数値が異なる。日本語の資料は 100/80/60/40）。
- **水見式**: 水を入れたグラスに葉を浮かべ、手をかざして練を行う。強化＝水の量が変わる／変化＝水の味が変わる／放出＝水の色が変わる／具現化＝水に不純物が出る／操作＝葉が動く／特質＝それ以外の変化（例: 葉が枯れる）。
- **性格の傾向**（資料で確認できたのは強化・変化のみ。他は記憶）: 強化＝単純で一途／変化＝気まぐれで嘘つき／放出＝短気で大雑把／具現化＝神経質／操作＝理屈屋でマイペース／特質＝カリスマ性のある個人主義者。
- **制約と誓約**: 自分に制約を課すほど、能力が強くなる。

## 研究 2: Ver1 の資産
- **語彙 2,520 語**（ステージ 42 個）。カテゴリ: 用語 1,647／行動 307／台詞 233／**キャラクター 139**／**能力 93**／道具 61／場所 35／組織 5。→ **図鑑**の見出し語になる。
- **ボスの企画**（`BOSS_SYSTEM_PLANNING.md`）: 章ごとに固有のルール — 集中（5 連続で次のミスを無効化）／フロア制限（時間で敵が強化）／刻限（90 秒・終盤は高速）／スタミナ（ミスで減り、コンボで回復）／複数形態／王の試練（4 フェーズ）／縛りと誓い（複数の制限が同時に働く）。報酬: メダル・ノーダメージ・パーフェクト・スピード・コンボのボーナス、マスターバッジ、称号。
- **素材**: 曲 3（＋行進曲 1）、効果音 6、キービジュアル 1、ボス画像 2（ほかは仮置き）。
- **こちらで作ったもの**: Blender 製のライセンス風カードとトランプ、念の段階（コンボ）、ボス戦・ステージ・入口。

## コンセプト: 「念で読む、自分の打鍵」
| 原作の設定 | ゲームでの意味（打鍵学習に対応） |
|---|---|
| 四大行（纏・絶・練・発） | 練習の**型**: 纏＝基礎／絶＝静かに正確に／練＝速さ／発＝自分の弱点から作る技 |
| 六系統・六性図 | 打鍵データを 6 軸に整理する**診断**（六角形のグラフ） |
| 水見式 | 診断を**見せる儀式**（グラスの 3D。系統ごとに反応が違う） |
| 制約と誓約 | 任意の**縛り**（ガイドなし・ノーミス・無音など）を選ぶと、報酬が増える |
| 凝・円 | 練習の**補助**（凝＝弱点キーを強調／円＝次のお題を先に見せる） |
| ハンターライセンス | プレイヤーの**カード**（級位・系統・戦績を 3D のカードに表示） |
| キャラ・能力・道具・場所 | **図鑑**（ステージで出会った語が記録され、語ごとの習熟が分かる） |
| ボスごとの固有ルール | 弱点に対応した**ボスの技**（Ver1 の企画を、弱点と結びつけて再設計） |

## 柱 1: 念系統診断（最優先）
打鍵ログから 6 軸を 0〜100 で求め、六角形で示す。**軸の定義（案。仕様書 `docs/spec/nen-types.md` で確定し、テストで固定する）**:

| 系統 | 軸の名前 | 求め方（案） | 使うデータ |
|---|---|---|---|
| 強化 | 速さ | 実効速度を級位の表に当てはめる | `kpm`（正確率が基準以上の練習） |
| 操作 | 制御 | 正確率と打鍵効率 | `accuracy`・`efficiency` |
| 放出 | 到達 | 小指・端のキー（遠いキー）の遅延が、全体に比べてどれだけ小さいか | キー別遅延＋運指（`fingering`） |
| 変化 | 適応 | パック（かな・英字・記号・短文）が替わっても、速さが落ちない度合い | パック別の速度の差 |
| 具現化 | 形 | 数字・記号・英字のキーの正確率 | キー別統計 |
| 特質 | 安定 | リズムの一貫性と、長い文での持久力 | `consistency`・短文パック |

- 各軸は最低試行数に満たなければ「データ不足」と表示し、点を描かない（統計のグラフと同じ原則、`MIN_SAMPLE`）。
- **自分の系統**＝最も高い軸。**修行の提案**＝最も低い軸と、そこを鍛える練習（ステージ・ボス・型）への導線。六性図の隣接関係は「伸ばしやすさ」の**演出**として使う（学習効果の主張はしない）。
- 診断は**打鍵ログから毎回計算**する。保存しない。
- グラフは `dataviz` の手順（色の検証・ツールチップ・表ビュー・キーボード操作）に従う。

## 柱 2: 水見式（診断の儀式）
- 診断を開くと、グラスに葉が浮かび、練でオーラを込めると系統に応じた反応が出る（強化＝水があふれる／変化＝水の味の表示／放出＝水の色が変わる／具現化＝不純物の粒／操作＝葉が回る／特質＝葉が枯れる）。
- Blender でグラス・水・葉のモデルを作る（オリジナルの造形）。**結果は文字でも出す**（例:「水があふれた → 強化系」）。演出オフでは結果の文字だけ。
- 打鍵ごとの手応え（HUD の水位）にも同じグラスを使う（PLAN のフェーズ A）。

## 柱 3: 修行の型（四大行）
既存の `Play` を土台に、モードとして足す。記録のモードは `train:<型>`。
- **纏（基礎）**: 今の練習・ステージ。
- **絶（静寂）**: 音・演出・ガイドを最小にし、ミスのない打鍵を目指す。ランクはミス数で決める。
- **練（速さ）**: 制限時間内にどれだけ打てるか（時間は注入した経過時間で判定）。
- **発（自分の技）**: 弱点キー・弱い連接から、その人だけの練習を作る。技には弱点から名前を付ける（例:「『k』の型」）。
- 補助: **凝**（弱点キーの強調）、**円**（次のお題のプレビュー）。判定には影響しない表示だけ。

## 柱 4: 制約と誓約（縛り）
- ボス戦・ステージの開始前に、任意の縛りを選ぶ: ローマ字ガイドなし／運指ガイドなし／ミス 0／無音／時間半分 など。
- 縛りの数だけ、報酬（メダルの段階）が増える。**判定・計測は変えない**（縛りは表示と敗北条件にだけ作用）。縛りを付けた記録は、モードに縛りの印を残し、通常の統計と混ぜずに集計できるようにする。
- ガイドなしは、ブラインドタッチの練習として意味がある（学習の目的に合う）。

## 柱 5: 図鑑とライセンス
- **図鑑**: Ver1 の語彙のカテゴリ（キャラ・能力・道具・場所・組織 = 約 330 語）を見出しにする。ステージで打つと「出会った」印が付き、語ごとの正確率・回数（=習熟）が分かる。初版は名前と習熟だけ。**説明文は、主要な人物・能力（約 40）から少しずつ書く**（原作の記述の正確さの確認が要るため、量で押さない）。
- **マイライセンス**: 3D のカードに、ハンターネーム（設定）・級位に応じた星・系統・ボス討伐数を表示する。

## 柱 6: ボスの技（弱点と結びつける）
Ver1 の企画を、単なる難化でなく**弱点への働きかけ**として再設計する。すべて縛りの設定と同様に、判定は変えず、表示と敗北条件にだけ作用し、無効にできる（アクセシビリティ）。
- ヒソカ: トランプで、ときどき 1 語の読みの一部が隠れる（先を読む力）。
- クロロ: スキルハンター — 直前に間違えたキーの運指ガイドを、その語だけ奪う（弱点を意識させる）。
- ビスケ: スタミナ — ミスで減り、コンボで回復。
- メルエム: 王の威圧 — ミスの余裕 1 回（現状）に、フェーズごとの条件。
- ネテロ: 百式観音 — 100 打鍵の連続（練習の持久力）＋縛りの同時適用。
（時間・攻撃予告・報酬は PLAN のフェーズ B と統合する）

## 柱 7: 見た目・音・設定への浸透
- **章ごとの配色**: 章のアクセント色をテーマのデータに持たせ、ステージ選択と練習画面に反映する。色は既存の**コントラスト検証**に通す。
- **背景と小道具（3D）**: 章ごとの小道具を Blender で作る（案: 天空闘技場の塔／幻影旅団の紋章／G・I のスペルカード／暗黒大陸の門）。すべてオリジナルの造形。
- **音**: 曲は Ver1 の 3 曲で足りない場面がある（ステージ選択・図鑑・診断）。**手元の素材か、Web Audio で合成した短い効果音**（段階の上昇・水見式・図鑑の発見）を足す。
- **設定**: ハンターネーム／縛りの既定／補助（凝・円）／図鑑の表示。

## 実装の順（提案）と規模
1. **念系統診断**（仕様書 → 軸の純関数とテスト → 六角形のグラフ）— 中。**水見式のグラス**を同時に（Blender ＋ three.js）— 中。
2. **修行の型**（絶・練・発、補助の凝・円）— 中。練習の推奨（PLAN のフェーズ D）と合流できる。
3. **制約と誓約**（縛り）とメダル — 中。ボス戦の拡張（PLAN のフェーズ B）と合流。
4. **図鑑**（見出し語と習熟）— 中。マイライセンス — 小〜中。
5. **ボスの技**、**章ごとの配色・小道具・音** — 大。順に足す。

## 素材のお願い（あるとよいもの。無くても進められる）
- ボス画像（クロロ・ビスケ・メルエム・ネテロ。いま仮置きで表示していない）
- 章ごとの背景・イラスト、キャラクターの立ち絵（図鑑・ライセンス用）
- 効果音: 念のオーラ、水見式の水音、図鑑のページ、ボスの技
- 曲: ステージ選択・診断・図鑑用（いまは Ver1 の 3 曲を使い回し）

## リスクと対応
- **原作の記述の誤り**: 出典を確認できた事実と記憶を分けて書く（本書）。図鑑の説明は少数から、確認して足す。
- **診断の根拠が弱い**: 「遊び」と明記。軸の定義を仕様書とテストで固定し、データ不足を隠さない。
- **縛りが計測を汚す**: 縛り付きの記録は印を付けて分け、通常の統計・級位の判定に混ぜない。
- **作り込みが打鍵の邪魔になる**: 演出は描画だけ、打鍵中の画面には新しい動く要素を足さない（診断・図鑑・ライセンスは練習外の画面）。
- **素材の量**: 3D・画像・曲は増やすほど配信量が増える。テーマを選んだときだけ、必要な場面の分だけ読み込む。
