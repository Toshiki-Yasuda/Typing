## 1. これは何か
日本語ローマ字入力のタイピング練習アプリ（個人学習用・PC の物理キーボード専用）。**正しく判定・計測でき、弱点を克服できること**が最優先。
旧版（HUNTER×HUNTER 題材の [Mobile-](https://github.com/Toshiki-Yasuda/Mobile-)）を原型に、コアを作り直した Ver.2。旧版の設計は引き継いでいない。
- リポジトリ: `Toshiki-Yasuda/Typing` / 公開: https://toshiki-yasuda.github.io/Typing/ （`main` への push で自動デプロイ）

## 2. オーナーの決定（覆さない）
- コアを先に。モチーフ・テーマは**オーナーが別に用意**する（コアに固有名詞・原作要素を入れない）。
- 個人学習用。PC・物理キーボードのみ（スマホ・PWA・かな入力・AZIK は対象外）。
- ローマ字入力。**正確さが最優先**。設計の細部は「一般的なタイピングゲームとして適切な方針」でAIに一任されている。
- 進め方: 確認なしで、キリのいいところまで自走してよい。

## 3. 運用ルール（重要）
- 機能ごとにブランチを切り、**CI（check + e2e）が緑になってから**反映する。
- **`main` への反映は、オーナーが「メインに反映して」と言ったときだけ**（`git merge --ff-only` → push）。勝手に `main` へ入れない。CI が赤なら反映しない。
- PR は頼まれたときだけ作る。コミットメッセージ・コメント・ドキュメントは日本語（接頭辞 `feat(…):` `fix:` `test:` `docs:`）。
- push 前は `npm run check && CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test`（CI と同じ + E2E）。コミットは `&&` でゲートする（`;` で繋がない）。
- テストは「空振り」にしない: 実装を故意に壊してテストが落ちることを確認し、`cmp` で元に戻す。

## 6. 開発環境の要点
- Node + `npm ci`。`npm run check`（lint→型→テスト+カバレッジ閾値→ビルド）が CI と同じ。E2E は `dist` を配信するため、ソース変更後は再ビルドされる。
- クラウド環境の Chromium: `CHROMIUM_PATH=/opt/pw-browsers/chromium npx playwright test`。`playwright install` は不要。
- ランダムテスト（fast-check）は実行ごとにシードが変わる。まれな失敗は `FC_RUNS=40000 npx vitest run src/engine/property.test.ts` で再現・探索する。
- GitHub は `gh` が無く、MCP ツール（`mcp__github__*`）を使う。CI の結果は `actions_list` / `get_job_logs` で見る。

## 7. 過去に起きた落とし穴（再発防止）
- **property テストの失敗 = エンジンの不具合とは限らない。** 実際に起きた例: `zz-`（除外行 `z-` を IME が使った）はテストの前提漏れ、`nyye` は本物のエンジンのバグ、`っひぃ`（最適性）は総当りオラクルの打鍵数の数え違い（`hh`+`hyi` の `h` 共有）。反例が出たら、どの側が誤りかを切り分け、固定テストとして残す。
- 「15万回で反例なし」のような断定をしない（統計的な保証ではない）。
- 見た目の変更は jsdom では気付けない。実ブラウザでスクリーンショットを撮って確認する（ツールチップの色継承などの不具合を過去に発見）。
- E2E は画面が出てからキーを押す。誤入力には `1` を使う（`q` は「く」で有効）。
- `pkill -f` は自分のシェルを殺しうる。Playwright の strict モードで重複要素に注意。
- 旧版 Mobile- の `main` は `useTypingAnimation` 欠落でビルド不能（未修正。Ver.2 とは無関係）。
