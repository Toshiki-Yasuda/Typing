# 計画

「正しく計測でき、続けて上達できる」タイピングゲームを作る。Ver.1（Mobile-）は原型にとどめ、設計は引き継がない。

## 決定事項
| 項目 | 決定 |
|---|---|
| 用途 | 個人学習用。PC・物理キーボード専用。スマホ/PWAは対象外 |
| 方針 | コアを先に堅牢に。モチーフ・世界観は「テーマパック」として後から載せる |
| 入力 | ローマ字入力、JIS/US配列。判定は `KeyboardEvent.key`。かな入力・AZIKは対象外 |
| 出題 | 単語・短文（読みを打つ）、英単語・数字・記号。文章（漢字かな混じり）は後回し |
| 指標 | 打鍵数基準（KPM）。WPM換算は参考表示 |
| データ | 生の打鍵ログを保存し、統計は再計算。IndexedDB＋JSONエクスポート |
| 運用 | 機能ブランチ＋CI必須（lint・型・テスト・ビルド） |

## 設計原則
1. **正しさを先に証明する**。仕様書（`docs/spec/`）→ 生成した入力表 → テストの順で固め、その後に画面を載せる
2. **入力表は手書きしない**。データから生成し、Mozc表との突き合わせをCIに入れる
3. **判定と表示ガイドは同じ状態から導く**（Ver.1の二重実装を避ける）
4. **入力処理と描画を分ける**。演出でキー入力を遅らせない
5. **コアにIP要素を入れない**。名称・台詞・画像・音源はテーマパックへ
6. **コンテンツはデータ駆動**（JSON＋zodで検証。読みが打てない語は入れない）

## 調査から採用した設計
- 判定: 候補集合（NFA）。「ん」「っ」は次のかなから導く（emiel型）
- 練習: keybr型。キー別・連接別の遅延を指数平滑し、遅いものを重点出題。正確性優先
- 計測: Monkeytype型の式を打鍵基準に翻訳。ミス直後の遅延は別枠
- テーマ: CSS変数のJSON＋manifest。ロジックと分離

## Ver.1 から持ち越さないもの
原作由来の名称・台詞・画像・音源、自前ルーティング、統計/ボス記録の二重管理、表示ガイド用の別ロジック、`を`→`o` や 母音キーでの長音などの独自仕様。
