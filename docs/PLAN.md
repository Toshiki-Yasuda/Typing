# 計画

「正しく計測でき、続けて上達できる」タイピングゲームを作る。Ver.1（Mobile-）は原型にとどめ、設計は引き継がない。

## 決定事項
| 項目 | 決定 |
|---|---|
| 用途 | 個人学習用。PC・物理キーボード専用。スマホ/PWAは対象外 |
| 方針 | コアを先に堅牢に。モチーフ・世界観は「テーマパック」として後から載せる |
| 入力 | ローマ字入力、JIS/US配列。判定は `KeyboardEvent.key`。かな入力・AZIKは対象外 |
| 出題 | 単語・短文（読みを打つ）、英単語・数字・記号。文章（漢字かな混じり）は後回し |
| 指標 | 打鍵数基準（KPM）。WPM換算は参考表示 |
| データ | 生の打鍵ログを保存し、統計は再計算。IndexedDB＋JSONエクスポート |
| 運用 | 機能ブランチ＋CI必須（lint・型・テスト・ビルド） |

## 設計原則
1. **正しさを先に証明する**。仕様書（`docs/spec/`）→ 生成した入力表 → テストの順で固め、その後に画面を載せる
2. **入力表は手書きしない**。データから生成し、Mozc表との突き合わせをCIに入れる
3. **判定と表示ガイドは同じ状態から導く**（Ver.1の二重実装を避ける）
4. **入力処理と描画を分ける**。演出でキー入力を遅らせない
5. **コアにIP要素を入れない**。名称・台詞・画像・音源はテーマパックへ
6. **コンテンツはデータ駆動**（JSON＋zodで検証。読みが打てない語は入れない）

## 調査から採用した設計
- 判定: 候補集合（NFA）。「ん」「っ」は次のかなから導く（emiel型）
- 練習: keybr型。キー別・連接別の遅延を指数平滑し、遅いものを重点出題。正確性優先
- 計測: Monkeytype型の式を打鍵基準に翻訳。ミス直後の遅延は別枠
- テーマ: CSS変数のJSON＋manifest。ロジックと分離

## Ver.1 から持ち越さないもの
原作由来の名称・台詞・画像・音源、自前ルーティング、統計/ボス記録の二重管理、表示ガイド用の別ロジック、`を`→`o` や 母音キーでの長音などの独自仕様。

## 次のプラン（2026-09-30 時点）

### 現在地
コア（判定・計測・弱点・級位）に加え、テーマ HUNTER×HUNTER が一通り動く: 入口（ゲート・オープニング・タイトル）、ステージ選択（7 章 × 5 + ボス）、ボス戦とその演出、打鍵の手応え（念の段階）、BGM・効果音、3D（Blender 製のカード）、設定画面。
**遊んでの調整（実機）がまだ**。数値は仮のものが多い。

### 進め方
1. **フェーズ 0（オーナーの手作業・最優先）: 実機で一通り遊んで、値を決める**
   - 確認: 音が鳴るか（自動再生）／音量バランス（BGM・効果音・決定音）／3D の滑らかさ（重ければ「控えめ」「オフ」）／ボス戦・ステージの難しさ／演出の長さ（決着の約 3.4 秒、オープニング約 2.6 秒）。
   - 調整する値と場所: ステージのクリア基準（`session/stageProgress.ts` の 0.9）／ボスのランク基準（`session/bossBattle.ts`）／ミスの余裕・お題の数（`themes/hunterBosses.ts`）／段階の境目（`themes/themes.ts` の `feel`）／BGM の倍率（`sound/useGameBgm.ts`）／音量の既定（`settings/settings.ts`）。
   - 完了条件: 気になった点が `task.md` に上がっている。
2. **フェーズ A: 水見式のグラス（3D）** — 手応えを「見て分かる」形に。規模 中。
3. **フェーズ B: ボス戦の拡張（時間制限・攻撃予告・報酬）** — 規模 大。
4. **フェーズ C: ステージの順番解放（設定）** — 規模 小。
5. **フェーズ D: 練習の推奨（丁寧さを促す）** — 規模 小。学習の本筋なので、A・B より先でもよい。
6. **フェーズ E: 品質・公開**（性能の予算・セキュリティ・バックアップ・README・実機 a11y）— 随時。

順番の考え方: 0 が済むまで、値に依存する作り込み（B の難易度など）は増やしすぎない。D は小さく価値が大きいので、0 の結果を待つ間に進めてよい。

### フェーズ A: 水見式のグラス（3D）
- **狙い**: コンボの進み（次の段階まで）を、グラスの水位で見せる。段階に入ると水があふれ、葉が動く（原作の「水見式」）。
- **作るもの**: `art/hunter/build_models.py` に、グラス（透明）・水・葉のモデルを足す（bpy、オリジナルの造形）。`public/themes/hunter/models/` に glTF。three.js の小さなシーン（HUD の横、約 160×220px）。
- **設計**: 水位 = `LevelInfo.progress`（0〜1）。段階に入った瞬間に水があふれて色が変わる（色だけに頼らず、文字の HUD は残す）。描画だけで、打鍵と独立。標準＝動く、控えめ＝水位は変えるが動かさない、オフ＝出さない。
- **性能の予算**: シーンは 1 つだけ・低解像度・`requestAnimationFrame` は表示中だけ。打鍵の遅延を増やさない（計測して確認）。
- **完了条件**: プレビュー画像で造形を確認／水位が進みに一致するテスト／演出の強さ 3 種の挙動／E2E で canvas 描画と axe／HUD の文字は変わらず残る。
- **リスク**: 透明な素材は three.js で重い・見づらい → 不透明なガラス風＋縁の光で代用できる形にしておく。

### フェーズ B: ボス戦の拡張
- **時間制限**: `Boss.timeLimit`（秒、任意）。時間切れで敗北。**`BossBattle` は時計を持たない**（純関数のまま）。経過時間は入力として渡す（`tick(elapsedMs)`）。残り時間は文字で表示（色だけにしない）。
- **攻撃予告**: 一定間隔で「攻撃」が来る（Ver1 の 3 秒前の予告）。予告中に語を打ち終えると回避／間に合わないとミス扱い。数値は `Boss.attacks`（データ）。予告は文字＋カウントダウン。音・演出は控えめ設定に従う。
- **報酬**: ランクに応じたメダル/バッジ（`typing.boss.v1` を拡張、版を上げて移行）。結果画面とステージ選択に表示。
- **ランクの見直し**: 時間・回避を加える場合、`docs/spec/ranks.md` ではなくボス用の仕様を `docs/spec/boss.md` に新設し、テストと一致させる。
- **完了条件**: 仕様書 → テスト → 実装の順／時間・攻撃は fake timer でなく**注入した時刻**でテスト／変異で確認／E2E／既存の戦績が壊れない（移行のテスト）。
- **リスク**: 時間制限は「丁寧さ」と衝突しやすい。既定は無制限のボスを残し、時間制限は上位の章だけ。

### フェーズ C: ステージの順番解放
- 設定 `stageUnlock: 'all' | 'sequential'`（既定 `all`）。`sequential` では、前のステージのクリアで次が開き、章のボスは全ステージのクリアで開く。
- 解放の判定は**記録から計算**（`stageProgress`）。鍵の表示は「🔒 前のステージをクリアで開く」と文字で。閉じているステージは、リンクでなく無効のボタン（`aria-disabled`）にして理由を読み上げに出す。
- 完了条件: 判定の純関数の表テスト／画面のテスト／E2E／既定（all）で従来と同じ。

### フェーズ D: 練習の推奨
- 直近の練習の正確率が基準を下回ったら、速度より丁寧さを促す（結果画面とホームに 1 行）。基準は `metrics/rank.ts` の級位の正確率基準に合わせる。
- 純関数 `recommendation(summaries)`: 「直近 3 回の中央値が基準未満 → 丁寧さ」「連続で良好 → 速度に挑戦」。文言は日本語、根拠の数値を示す。
- 完了条件: 表テスト／画面のテスト（結果・ホーム）／過度に出さない（同じ助言を連続で出さない）。

### フェーズ E: 品質・公開（随時）
- **性能の予算**: バンドル（メイン gzip 144KB、3D の遅延チャンク 155KB）を予算として `docs/` に書き、CI で超過を検知。打鍵から描画までの遅延を実ブラウザで計測（3D・演出あり/なし）。大量の記録（数千セッション）での集計時間。
- **セキュリティ**: 依存の監査（`npm audit`）、CSP（three.js と `blob:`・`data:` の要否を確認）。`SAKI` は目隠しで鍵ではない（ADR 0001）。
- **バックアップの促し**: 一定期間書き出していなければ、ホームで案内。
- **README／ADR**: 現状に合わせる。
- **実機 a11y**: スクリーンリーダー・ハイコントラストでの確認（オーナー）。入口・ステージ・ボス戦の新画面を含める。
- **細部**: ステージの「同じお題でもう一度」で表記（漢字・カタカナ）を復元／`E2E` を負荷に強くする（待ち方の統一）。
