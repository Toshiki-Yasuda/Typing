# typing-dev

詳細は `docs/WORKFLOW.md`。まず `docs/HANDOFF.md`（現状）と `task.md`（バックログ）を読む。

## サイクル（1 スライス = 半日以内）
1. 仕様を短く固める（`docs/spec/`・ADR。数値は「仮」と明記）。
2. **純関数とテスト**（打鍵の判定・計測に触れない）。
3. **変異**: `scripts/mutate.sh <名前> <ファイル> <sed式> <テスト...>`。生き残りはテストを直す（等価なら冗長なコードを消す）。
4. 画面と部品のテスト。演出の強さ（標準/控えめ/オフ）と標準テーマで出ないことを確認。
5. E2E（axe 含む）。待つ条件を明示（ゲートのフォーカス、アニメの完了）。
6. 見た目は `node scripts/shot.mjs <場面>` で撮って画像を読む。
7. `scripts/verify.sh`（check ＋ E2E）。
8. 文書（ADR・spec・task.md・HANDOFF）を同じコミットで更新。
9. 日本語でコミット（`feat(…):` 等 + Co-Authored-By）→ push → CI を確認。

## 守ること（要点）
- `main` に反映するのは、オーナーが「メインに反映して」と言ったときだけ。CI の check と e2e が緑なのを確認し、`git push origin <sha>:refs/heads/main`。
- 指標は打鍵ログから再計算する。保存しない。判定・計測を演出や縛りで変えない。
- 色だけで伝えない。点滅させない。飾りは `aria-hidden`。新しい画面は h1 と axe。
- コアに固有名詞を置かない（テーマは `src/themes/` と `public/themes/`）。
- オーナーの返事待ちで止まらない。推奨を決めて進み、報告に「決めたこと」を書く。

## 落とし穴
`page.evaluate` でタイマーを全消去しない／`pkill -f` を使わない／モックは呼ばれる関数を全部持つ／語の途中で止めない／負荷で落ちるE2Eは待ち方を直す。
